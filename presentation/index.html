Identity

state + year form the composite key. One document per pair, enforced by a unique index.

Seven measures

Each crime head is a numeric field. Zero is a real observation — none reported — not missing data.

Derived total

Stored at write time so a read never re-adds seven fields just to show a headline.

Projection

The API reads with { _id: 0 }. MongoDB's storage id is not part of the contract.

Homogeneous by contract. MongoDB does not enforce this shape; the ETL does. Every document is written by the same normalizer with the same keys.
BSON types stay stable: strings for names, 32-bit integers for counts, and one synthetic _id that never leaves the database.

NoSQL design decisions

Embed

All seven measures are read together, so they live together in one document.

Reference

Labels and colors are shared across facts. Store them once, keyed by a stable string.

Materialize

The derived total and the filter arrays are written once, not recomputed per request.

Validate

The ETL enforces the shape. MongoDB does not — the contract is an application guarantee.

Flexible schema is not the goal. A stable document contract is.
Auth and saved views add users, sessions and saved_views — operational collections, not part of the crime fact model.

06 · Indexes

The grain is the index.

Three indexes on crime_records. The unique compound index is the integrity rule; the other two serve access paths.

unique{ state: 1, year: 1 }

One document per state-year pair. This is the integrity constraint for the fact collection.

serves → exact state + year lookup · duplicate writes rejected
range{ year: 1 }

Year windows and timeline slices, including open-ended ranges.

serves → 2014 → 2021 · bounded index scan
filter{ state: 1 }

One state across all 21 years and the state dossier route.

serves → Kerala · Goa · $in becomes index seeks

How the planner uses them

state + yearIXSCAN on the compound index, then one document fetch.
year rangeBounded index scan, no full collection scan.
state $inOne index seek per value, merged into the result.
Integrity, not just speed. The unique index is what makes replaceOne + upsert safe: the database itself refuses a second fact for the same state-year.
$createIndex({ state: 1, year: 1 }, { unique: true })at import
Indexes are provisioned by scripts/import-mongo.mjs, not at request time. Re-running the import upserts by the same key.
07 · Access layer

One function hides the database.

Every route calls getStore(). It connects once, reads with a projection, and caches the result in module scope.

lib/db.ts / simplifiedTS
let mongoStore: Store | null = null;

export async function getStore() {
  if (MONGODB_URI && !mongoStore) {
    const db = await connectMongo();
    if (db) {
      const records = await db.collection("crime_records")
        .find({}, { projection: { _id: 0 } })
        .toArray();
      // metadata: years, states
      mongoStore = { records, years, states, ... };
    }
  }
  return mongoStore ?? seedStore;
}

09 · Aggregation

Aggregation is the read model.

One pipeline folds 736 documents into a 21-point national series — match, group, sort, project.

national series · 2001—2021pipeline
db.crime_records.aggregate([
  { $match: { year: { $gte: 2001, $lte: 2021 } } },
  { $group: { _id: "$year", cases: { $sum: "$total" } } },
  { $sort: { _id: 1 } },
  { $project: { _id: 0, year: "$_id", cases: 1 } }
])

Narrow

$group

11 · Trade-offs

Why this model holds at this scale.

One fact collection, two lookup collections, one metadata collection — and no joins anywhere in the read path.

01 · EMBED

Embed what you read together

All seven measures arrive in one fetch. The dashboard never reassembles a fact from separate tables.

02 · REFERENCE

Reference the vocabulary

State names and crime labels live once, keyed by stable strings. No label is copied into 736 documents.

03 · MATERIALIZE

Denormalize the total

2,212 is written once and read without re-summing seven fields. The trade-off is a write-time computation.

04 · SCALE

Cache, then scale out

One read per process today; shard on state and move aggregation server-side tomorrow.

What we did not build: a collection per crime head, a join table, or a client-side database. None of those simplify this dataset.
At 736 documents, one collection read beats a database round-trip per filter. The model is ready for a server-side pipeline when the data grows.
